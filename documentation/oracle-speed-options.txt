Oracle / HDB over the network — speed options (discussion; not implemented yet)
================================================================================
Context: Internal HDB uses many short SQL round-trips (per SDID × date chunk ×
thread). Wall time is usually dominated by network RTT + Oracle parse/execute,
not by local Python after the PATH bug fix.

Current shape (USBR.sqlRead)
----------------------------
- Estimate points for the full date range → split into date sub-ranges (chunks)
  when over queryLimit rows.
- For each (SDID, chunk): open connection, run interval SQL, optionally r_base
  SQL, close connection.
- Up to maxThreads (15) workers pull those tasks.
- Map/lookup tables (agency, method, …) use one connection first.

Why a 2-year × many SDIDs query is slow
---------------------------------------
- Tasks ≈ (# HDB series) × (# date chunks). Chunks grow with range/interval.
- Each task pays connect + 1–2 SQL round-trips over the internet (or WAN).
- Two HDB homes (LCHDB + YAOHDB) are separate query groups; still same Instant
  Client process, but each sqlRead has its own worker pool and task list.

Options (with Seifer decisions)
-------------------------------

A) Batch SDIDs in one SQL (WHERE site_datatype_id IN (...))  — IMPLEMENTED (retest)
   - One round-trip for many series in the same chunk/DB.
   - Biggest win for “100 parameters” style lists.
   - Need careful bind limits, result split by SDID, memory for wide results.
   DECISION: Do after C validated.
   CODE: sdidBatchSize=25; tasks = (batch, dateRange); _buildMultiSdidQueries IN-list;
         results split by SDID into same result shape as before.

B) Fewer / smarter date chunks  — REMOVED
   - Too risky (timeouts, huge result sets).

C) Connection reuse per worker (or per sqlRead)  — IMPLEMENTED (retest)
   - Worker opens one connection and reuses it for many tasks instead of
     connect/close per (SDID, chunk).
   - Cuts login/handshake cost a lot over the internet.
   - Must be thread-safe (one connection per thread only).
   DECISION: Prefer this first when we pick up Oracle speed work on bug-smashing.
   CODE: USBR.sqlRead worker() opens oracleConnection once; queryTask uses
         executeCustomQueryWithRetry; close in finally after queue empty.

D) Connection pool (oracledb pool)
   - Acquire/release instead of full connect each time.
   DECISION: Deferred — C already reuses one session per worker for a full sqlRead.
             Revisit pool if we need share-across successive queries / mapConn merge.

E) Database links / single DSN strategy
   - Already uses primary DSN + @db_link where links exist (3 HDBs linked;
     others are not). No new product work unless more links appear.
   DECISION: Already in place where possible; leave as-is.

F) Parallelism tuning (maxThreads)
   - More threads can help or hurt.
   DECISION: Leave current threading as-is while testing C (and later A/D).
             Do not push thread count without measurement.

G) Reduce metadata work when not needed  — REMOVED
   - r_base / maps needed for details context menu.
