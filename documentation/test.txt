Current Tests
--------------------------------------------------------------------------------
[ ] Windows update prompt does not mention the launcher
   Steps:
     a. On a Windows install, when a newer version is offered, the
        Update available text ends with "Download, then hit Restart to apply."
     b. It does not say the launcher will be updated. The app does not
        know that yet. The second-restart prompt still appears later,
        and only when a launcher file actually has to change.

[ ] Same launcher does not ask for a second restart
   Steps:
     a. Update a Windows install whose Data Doctor.exe and applyUpdate.cmd
        are already the ones in the new package (RC 2.2 to 2.3 used the
        same launcher).
     b. After the first Restart, Data Doctor opens. There is no second
        restart prompt.
     c. applyUpdate.cmd.new is not left next to Data Doctor.exe.

[ ] A real launcher change still asks for the second restart
   Steps:
     a. When the new package's applyUpdate.cmd text differs, or the
        embedded Python is a different build, the first apply leaves
        applyUpdate.cmd.new and/or python-embed.next.
     b. The next start still shows the second restart prompt.
        Restart finishes those files.

[ ] 3.0.0 reaches the current launcher command
   Steps:
     a. From a 3.0.0 install, take the in-app update. The first zip is
        the Python zip. That updater does not download the Windows zip.
     b. Restart. The app comes up on the new code and asks for the
        Windows package even if the version number already matches.
        applyUpdate.cmd is the current command (python-embed, then
        Project Files, then .venv).
     c. Download and Restart. Data Doctor.exe is replaced and
        pythonFiles\python-embed is installed. A second restart appears
        only if the command or that Python could not be replaced while
        they were in use.

[ ] Regression uses every usable series, upstream or downstream
   Steps:
     a. Select two or more upstream series and the downstream you want
        to predict. Right-click, Regression, predict the downstream.
        The equation includes each upstream that moves with it, and the
        label shows a lag for each. A negative lag means that series leads.
     b. Select several downstream series and predict a gage above them
        (or predict a middle gage from gages on both sides). Each
        downstream that moves with the target stays in the equation.
        Its lag is positive (it trails).
     c. Add a series that does not belong (flat noise, or a column
        with no overlap). It is left out. Under the stats, a warning
        names it and says why (no usable lag, does not move the fit,
        or not enough overlapping rows). The usable series stay.

[ ] Regression tab shows the regression icon
   Steps:
     a. Open Regression from a query. The Regression tab icon is the
        hand-drawn scatter with a fit line on a dusty rose tile.

[ ] Plotter HDB uses SQL when the API misses
   Steps:
     a. Oracle credentials are saved. Plot a USBR Oracle series (LCHDB,
        UCHDB2, YAOHDB, or another HDB) whose public API call fails or
        does not include that SDID.
     b. The series still plots. The log says it is trying the Oracle connection.
     c. USBR-PNHYD, USBR-GPHYD, USGS, and Aquarius stay on the API.
        A series the public API returns with no points is not read from SQL.

[ ] Mac package script
   Steps:
     a. From project root: python scripts/packageMac.py --skip-venv
     b. Zip contains Data Doctor.app, Data Doctor.command, Clear Quarantine.command,
        pythonFiles/python-embed-arm64 and python-embed-x86_64 (bundled CPython).
     c. On a Mac: unzip, Right-click Data Doctor.app → Open (Gatekeeper). No system Python.
     d. If blocked: Clear Quarantine.command (Right-click → Open), then the app.
     e. Optional on Mac only: python scripts/packageMac.py --app → frozen PyInstaller .app.
