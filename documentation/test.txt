Oracle speed decision (keep C)
--------------------------------------------------------------------------------
[x] Keep connection reuse (C); do NOT re-add batch SDIDs (A).
    Why A can be slower even if fewer round-trips:
      - Larger result sets / more bytes over WAN per query
      - IN-list plans can be worse than equality on (SDID, time) indexes
      - Extra Python split/group work
      - After C, connect cost is already gone — day queries gain little from A
      - Oracle result/plan cache can favor repeated single-SDID shapes
    2-year: C left HDB ~30s behind Aquarius — good enough.
