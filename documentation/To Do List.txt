-GitHub issue from the app (crash + manual) — DISCUSSION / PLANNING ONLY (do not implement yet)
    -Yes, the GitHub Issues API can create issues (POST /repos/S31F3R/DataDoctor/issues).
     Repo already has issues enabled. Body can include app.log text.
    -Do NOT ship a PAT / GitHub App secret inside the desktop app. Anyone can extract
     it and file spam as Data Doctor. That rules out "app posts the issue by itself"
     unless we add a tiny backend or a GitHub App that mints short-lived tokens.
    -Safe options to pick from later:
        A. Report button / crash dialog opens a pre-filled Issues URL
           (https://github.com/S31F3R/DataDoctor/issues/new?title=...&body=...)
           User must be logged into GitHub. No secret in the app. Cannot attach
           a file via the URL; log text can be copied into the body (size limits).
        B. Same as A, plus "Copy app.log" / "Open log folder" so the user pastes
           or attaches the file themselves in the GitHub UI.
        C. Crash dialog writes a local dump and offers A+B. Uncaught hooks already
           log tracebacks to app.log (Logic.installExceptionHooks).
        D. Only if we want true no-login filing: a small relay (Cloud Function /
           GitHub App) that accepts a dump and opens the issue. Needs hosting +
           abuse limits. Not for v3.0.
    -Recommendation: C for first release (crash + a Tools/About "Report an issue"
     that pre-fills version, OS, and log tail). Revisit D if users will not have
     a GitHub account.
    -Also useful later: a GitHub issue template (bug / crash) so the URL lands
     on a form instead of a blank markdown box.
